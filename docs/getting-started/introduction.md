# Introduction

`drone-capability` measures how an algorithm and a flight computer turn into what a drone can do on a mission: how fast it can safely fly, how far it can go, and what that costs in endurance. A designer can then pick the algorithm and the compute part from a mission requirement rather than from a datasheet. The [repository README](../../README.md) describes the full design. The sister mission repos (racing, scout, inspection, ISR, interceptor and nano drones) state their requirements in its units.

## What is here

| Path | What it is |
|---|---|
| [`models/`](../../models/) | The capability models (Python, numpy and scipy). They reproduce the Bauersfeld & Scaramuzza energy-optimal-speed model, add compute power, mass and latency to it, and estimate each mission's capability for each compute option. |
| [`models/data/`](../../models/data/) | The estimator's inputs: airframes, compute options (`compute.json`) and missions. Placeholders are tracked in [#8](https://github.com/branes-ai/drone-capability/issues/8). |
| [`bench/`](../../bench/) | The Phase 2 measurement harness. It runs stand-in L1 pipelines on a target at mission rate, under concurrent load, and records latency and power. |
| [`bench/results/`](../../bench/results/) | The measurements, one folder per target, published on the [results page](../benchmarks/results.md) |
| [`docs/benchmarks/`](../benchmarks/optimal-speed.md) | The benchmark plans and the [benchmarking workflow](../benchmarks/workflow.md) |

## Running the models

From the repo root:

```sh
python3 models/pen_and_paper.py        # reproduces the paper's Mavic 3 example
python3 models/estimate.py             # the mission-capability estimator
python3 models/compute_scenarios.py    # the estimate tables in the optimal-speed plan
python3 models/plot_figures.py         # the plan's figures (needs matplotlib)
python3 -m unittest discover -s models
```

## Measuring a target

The [benchmarking workflow](../benchmarks/workflow.md) is the full procedure: preparing a target, running a matched CPU and accelerator set, publishing the results, and turning them into a `compute.json` entry. In short:

```sh
python3 bench/run.py --pipeline racing --target orin-nano-super-25w-gpu --power jetson \
    --provider tensorrt --soak 60 --background scout --background inspection
python3 bench/summarize.py --page      # regenerate the results page
```

## Where the work stands

The optimal-speed plan runs in phases (tracked in [#4](https://github.com/branes-ai/drone-capability/issues/4)):
- **Phase 0, reproducing the paper:** done.
- **Phase 1, adding compute to the model:** done.
- **Phase 2, measuring the compute:** a Jetson Orin Nano Super and an Arduino Ventuno Q measured; masses still to be weighed.

The results so far are in the [plan](../benchmarks/optimal-speed.md#phase-2-results-first-two-targets).

## This site

The site is generated by [docs-kit](https://github.com/branes-ai/docs-kit) from `docs/`, and redeploys on every merge to main. To see it locally, run this in `docs-site/` (Node 22):

```sh
npm ci
npm run dev       # http://localhost:4321/
npm run build && npm run check
```

The plan's figures are `<picture>` elements (a light and a dark PNG), so that GitHub shows the one that matches the reader's theme. docs-kit doesn't copy images referenced from raw HTML, so `docs-site/scripts/html-figures.mjs` copies them before `dev` and `build`.
